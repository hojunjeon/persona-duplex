# 페르소나 작성

기본 페르소나는 `gateway/personas/<id>.yaml`에 포함됩니다. 이 파일은 이미지 안의
읽기 전용 기본값입니다. UI에서 만드는 사용자 페르소나는 `data/personas/<id>.yaml`에
저장되며, 컨테이너를 다시 시작해도 남습니다.

## UI에서 만들고 선택하기

1. `2. 실시간 대화`의 `새 페르소나 만들기`를 펼칩니다.
2. 이름·정체성·관계를 입력하고, 말투·행동·경계·추임새는 한 줄에 하나씩 적습니다.
3. 기본 문장 수(1~8)를 정한 뒤 `페르소나 생성`을 누릅니다.
4. 생성이 끝나면 목록에서 새 페르소나를 선택하고, 목소리를 고른 뒤 대화를 시작합니다.

생성 버튼은 페르소나만 저장하고 선택 목록을 갱신합니다. 대화를 자동으로 시작하거나
목소리 목록을 다시 불러오지 않습니다. 대화 중에는 페르소나를 바꿀 수 없고, 다음
대화를 시작할 때 선택이 적용됩니다.

서버는 사용자 입력을 정규화하고 안전한 ID(`custom-<uuid>` 또는 안전한 slug)를
생성합니다. 이름·정체성·관계는 각각 200자, 배열은 최대 16개·항목 200자·전체
2,000자로 제한하며 제어 문자는 거부합니다. 기본 페르소나를 덮어쓰거나 같은 ID를
두 번 저장할 수 없습니다.

```yaml
name: 노드
identity: 냉정하고 정확한 기술 분석가
relationship: 사용자의 설계 검토자
speaking_style:
  - 결론부터 말하고 근거를 짧게 붙인다.
  - 과장 표현을 쓰지 않는다.
behavior:
  - 가정과 확인된 사실을 분리한다.
  - 구현 요청에는 실패 조건까지 말한다.
boundaries:
  - 성능 수치를 만들어내지 않는다.
  - 사용자의 신원이나 기억을 사칭하지 않는다.
backchannels:
  - 음.
  - 확인했어.
  - 계속 말해.
max_sentences: 4
```

## 좋은 규칙

- 음성으로 들었을 때 판별 가능한 행동을 적습니다.
- “똑똑하게”, “매력적으로”보다 “결론을 첫 문장에 말한다”가 낫습니다.
- 말투와 사실 정책을 분리합니다.
- 추임새는 짧고 3~6개 정도로 제한합니다.
- 한 답변의 기본 문장 수를 작게 둡니다.

## 피할 규칙

- 매 문장마다 특정 감탄사를 넣기
- 사용자인 척 말하기
- 실제 경험·기억·권한이 있다고 주장하기
- 내부 추론을 소리 내어 설명하기
- Markdown 목록을 그대로 낭독하기
- 긴 배경 설명 뒤에 결론 말하기

## 목소리와 페르소나는 별개

페르소나 YAML은 텍스트 내용과 말투를 제어합니다. Qwen TTS 참조 음성은 음색과 음향적 운율 조건을 제공합니다. “차분한 분석가” 프롬프트만으로 기준 녹음의 높은 톤을 완전히 낮추지는 않습니다. 최종 페르소나에 가까운 발성으로 참조 음성을 녹음해야 두 조건이 같은 방향으로 작동합니다.
